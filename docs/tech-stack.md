# 기술 스택 결정 문서

## 선택한 스택

- **HTML5 Canvas**
- **Vanilla JavaScript** (프레임워크/라이브러리 없음)

## 결정 이유

### 1. 소규모 토이 프로젝트
이 프로젝트는 트릭컬의 신규 캐릭터 두두를 소재로 한 크롬 공룡 게임 클론으로, 학습/실험 목적의 소규모 토이 프로젝트다. React, Vue, Phaser 같은 프레임워크를 도입하면 얻는 이점보다 설정·학습·유지보수 비용이 더 크다. 프로젝트 규모에 맞는 가장 가벼운 스택을 선택한다.

### 2. 원본 크롬 공룡 게임과 동일한 구현 방식
벤치마킹 대상인 크롬 오프라인 공룡 게임 자체가 Canvas + Vanilla JS로 만들어져 있다. 같은 방식을 쓰면 구조를 참고하거나 비교하기 쉽고, 구현 중 막히는 부분이 생겨도 참고할 사례가 명확하다.

### 3. 빌드 도구가 필요 없음
번들러(webpack, vite 등)나 트랜스파일러 설정 없이 `index.html` 파일 하나를 브라우저에서 바로 열어 실행할 수 있다. 토이 프로젝트에서 빌드 파이프라인을 구성하는 것은 불필요한 오버헤드다.

### 4. 게임 루프 기반 2D 렌더링에 적합
Canvas는 `requestAnimationFrame` 기반의 게임 루프(지우기 → 상태 갱신 → 다시 그리기)에 최적화된 방식이다. DOM 엘리먼트를 매 프레임 조작하는 방식과 달리 리플로우/리렌더링 오버헤드가 없어, 공룡/장애물처럼 빈번하게 위치가 바뀌는 2D 그래픽을 다루기에 적합하다.

### 5. 외부 의존성 없음
npm 패키지나 CDN 라이브러리에 의존하지 않으므로 버전 관리, 호환성 이슈, 의존성 업데이트 같은 유지보수 부담이 없다. 토이 프로젝트의 수명 주기 동안 신경 쓸 거리가 줄어든다.

### 6. 임시 리소스 → 실제 리소스 교체가 쉬운 구조
현재 두두의 달리기 스프라이트를 구하기 어려운 상태라, 우선 임시 이미지(사각형 등)로 게임 로직(점프, 장애물, 충돌 판정, 스코어)을 먼저 구현하기로 했다. Canvas는 `drawImage()` 호출부만 교체하면 되므로, 추후 실제 스프라이트가 준비되면 로직을 건드리지 않고 그림 그리는 부분만 바꿔 넣을 수 있다.
